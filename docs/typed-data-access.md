# 数据类与 JSON 边界

自有服务代码的固定结构使用 Pydantic 数据类，通过属性读取和赋值。HTTP、数据库 JSONB、YAML 和 dbt 原生产物在入口转换；内部不使用 `TypedDict`，也不提供 `__getitem__`、`get` 等字典兼容方法。

## 已覆盖范围

- 存储记录：构建、任务、租约、部署、产物文件、元数据和变更日志。
- 嵌套载荷：任务请求、执行快照、失败诊断、构建验证摘要。
- 引擎与应用：目录、血缘、维度选项、查询输入、查询结果和时间范围。
- 配置：服务配置、实例与凭据引用、dbt profile、工程与依赖文件。
- 原生产物：manifest、catalog、执行结果、freshness、hook 和物化配置的类型化投影。
- HTTP 响应：构建、部署、资源、健康检查、版本及错误信息。

固定的服务协议拒绝未声明字段。发布证明与写入策略的布尔值使用严格布尔类型，拒绝字符串和数字冒充布尔值。第三方原生产物允许扩展字段，但本服务读取的字段均已声明；原生详情序列化保留扩展内容和原有缺省状态。

## 保留映射的具体场景

| 场景 | 原因与限制 |
| --- | --- |
| `api/limits.py` 的 ASGI scope/message | ASGI 规定输入与输出是映射，包含请求分块、断连事件和协议扩展；仅在中间件协议边界访问。 |
| `storage/postgres.py` 的 libpq 参数 | `parse_dsn` 输出和驱动调用接受动态连接参数，包括服务不定义的 SSL、认证等选项。固定修改仅为连接超时和会话 options。 |
| `storage/schema.py` 的 SQLAlchemy 反射 | SQLAlchemy 返回驱动定义的列元数据映射；仅在 schema 检查边界读取列名。 |
| 环境变量和驱动参数 | 键由操作系统、Git、dbt 或适配器定义，不能由有限的服务字段替代。 |
| 动态索引 | 资源 ID、文件路径、profile 名、实例 ID、列名和粒度都是运行时键；映射中的结构化值仍使用数据类。 |
| 原生扩展及任意 JSON 值 | `nativeDetails`、引擎过滤扩展、查询单元格值等由第三方或调用方定义；透传或递归规范化，不按未知固定字段解释。 |
| 序列化和框架调用 | `model_validate`、`model_dump`、JSONB、YAML、SQLAlchemy 选项和 JSON 响应需要映射；不把这些映射作为业务层记录传播。 |
| 测试中的协议样本 | HTTP 请求/响应、SQL 损坏数据和第三方原生产物样本保留原始 JSON，以验证边界拒绝行为和序列化兼容性。内部测试替身使用数据类。 |

`vendor/` 是上游 dbt/MetricFlow 依赖源码，不属于本次自有服务重构范围。

## 明确类型与字符串常量

自有服务代码禁止 `Any`，参数与返回值必须有明确类型；容器必须声明元素类型。开放 JSON 字段使用 Pydantic 的递归 `JsonValue`，包括原生扩展、查询过滤值和结果单元格。数据库的 `Decimal`、日期和时间在转换边界显式转成 JSON 字符串；任意 Python 对象和二进制值不能进入 JSON 载荷。引擎、表格和数据库行参数使用对应的具体类型。

`constants.py` 集中定义共享状态、错误码、环境变量名、文件与目录名、字段别名和第三方协议值；模块内专用错误文案使用有描述性名称的 `Final` 常量。相同语义使用同一个定义，已有局部常量可以作为共享定义的别名。文本相同但语义不同的值（如命令、资源类型、模板变量）分别命名。需要满足 `Literal` 参数契约的常量显式保留字面量类型。

以下字符串保留在原处：类型注解中的字面量、文档字符串、字段说明、数据库列注释、动态 f-string 的文本片段、空白和纯标点。SQL、正则和模板定义使用具名常量或保留在对应语言边界。测试中的协议输入和预期值保持独立，避免与实现共用常量而掩盖协议变更。

`test_explicit_types.py` 检查 `Any`（含别名和字符串注解）及未指定元素类型的容器；Ruff 检查参数/返回注解及 `ANN401`。`test_string_constants.py` 检查共享值重复定义和散落的运行时字符串。

## 验证方式

运行 `ruff check src tests` 和完整 pytest。数据库测试使用独立临时 PostgreSQL，真实 SDK 集成覆盖构建、部署、历史目录、四种查询模式和清理。新增测试覆盖字段拒绝、原生扩展无损、严格布尔证明、诊断脱敏和非 JSON 结果拒绝。

改动前已有 `test_vendored_sources_are_at_audited_commits` 失败：本地 vendor 提交与测试登记的审核提交不一致；本次不修改子模块或放宽该测试。

真实 SDK 集成测试要求测试数据库先通过 `Database.initialize()` 初始化，再启动 `Runtime`；生产运行时只检查结构，不隐式建表。

本轮最终全量结果：483 通过、3 跳过、1 个上述既有 vendor 审核版本失败；类型与常量静态守卫、Ruff 和 `git diff --check` 均通过。
