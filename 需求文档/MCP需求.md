# dbt-metricflow-service 面向 Agent 的通用 MCP 工具接入需求

> 历史需求（2026-11-18）。自 2026-11-25 起，MCP Server 由 Metric Platform 交付，接入说明和当前工具契约见该工程的 README。

## 1. 目标与交付边界

使用者向接入 MCP 的 Agent 询问“上月各渠道销售额是多少”，可以找到对应的指标定义、确认渠道维度、查询结果并追溯使用的构建版本。使用者也可以指定已有的 Git 提交发起构建，查看构建及关联部署的实际状态。

由 dbt-metricflow-service 项目交付一个 MCP Server，供支持 MCP 工具调用及标准输入输出（stdio）传输的客户端启动和调用。对话、选择工具和解释结果由接入方 Agent 承担。所有业务操作通过 dbt-metricflow-service 的公开 HTTP API 执行，沿用其校验、执行和状态语义。metricPlatform 无需新增 MCP 接口。首版范围不含自建 Agent、聊天界面、独立部署写接口及新的认证或租户体系。

## 2. 工具契约

下表为建议工具名。每项工具须可由 MCP 客户端发现，声明用途、必填参数、参数类型及业务约束，并返回结构化结果。开发时以服务端当前公开契约为准；如现有 HTTP API 缺少下表所需能力，请在交付说明中标明缺口。

| 工具 | 输入 | 调用方需要获得的结果 |
|---|---|---|
| `get_current_deployment` | 仓库、环境 ID、目标分支 | 当前生效的构建 ID 和提交版本。无生效部署时明确返回该状态 |
| `search_catalog` | 构建 ID、关键词，可选资源类型和分页参数 | 匹配的资源 ID、名称、说明、类型和下一页游标 |
| `get_resource` | 构建 ID、资源 ID | 该版本中的指标定义、说明和服务已公开的属性 |
| `get_available_dimensions` | 构建 ID、一个或多个指标资源 ID | 该指标组合可选的维度标识及服务支持的粒度等元数据 |
| `query_metrics` | 构建 ID、指标资源 ID、服务契约支持的分组、过滤、排序、时间范围及行数限制 | 列、行、构建 ID、提交版本、业务时区和实际时间边界。保留服务返回的结果限制信息 |
| `submit_build` | 仓库、分支、完整提交 SHA、执行快照、部署策略、幂等键，以及契约要求的追溯信息 | 已受理的构建 ID、当前构建状态及关联部署信息。工具收到受理结果即可返回 |
| `get_build` | 构建 ID | 构建状态、失败原因、目录和查询的可用性，以及关联部署的独立状态 |

## 3. 执行约束

- **版本一致性。** 用户指定构建时直接使用该版本。按当前部署分析时，先解析一次生效构建，后续目录、资源、维度及查询调用均显式传入同一个构建 ID。构建不可查询时返回原因，切换版本需重新选择。
- **指标与时间口径。** 查询使用目录返回的指标资源 ID 和维度接口返回的选项 ID。保留同名候选供调用方澄清。时间范围、粒度和结果值遵循服务契约，保留空值、数值类型、业务时区及边界语义；空结果返回列和空行集。
- **写操作。** 构建使用固定的提交、执行快照和幂等键。部署策略须显式传入。若选择成功后部署，在工具说明中标明副作用。网络中断且受理结果未知时，保留原幂等键；恢复操作沿用相同输入。只有服务返回部署成功才能报告已部署。
- **错误。** 参数非法、无生效部署、资源不存在、构建不可查询、服务不可达应可区分。保留服务提供的错误码、可重试标记及已知构建 ID；业务失败不得包装成成功的空数据。
- **本地配置。** 服务地址及现有服务所需的凭据由运行环境提供。工具参数与错误信息不暴露凭据值。标准输出专用于 MCP 协议，诊断日志写入标准错误。

## 4. 验收场景

| 场景 | 通过条件 |
|---|---|
| 跨客户端接入 | 使用两个独立的 MCP 客户端，通过 stdio 分别启动同一份 Server。在未安装专用 Skill 的情况下，两端均能通过 `tools/list` 发现上述七个工具及其输入结构，并通过 `tools/call` 读取同一测试部署，得到相同的生效构建 ID |
| 端到端分析 | 在有已知测试数据的环境询问“上月各渠道销售额是多少”。能定位指标、取得渠道选项并完成分组查询；构建、时间边界、列与行值同直接调用 HTTP API 一致 |
| 指标有歧义 | 准备两个匹配“销售额”的指标。搜索返回两个候选及可区分的定义；选择其中一个后，查询使用所选资源 ID |
| 分析期间发生部署 | 取得构建 A 后将当前部署切换到 B。继续使用 A 查询，得到 A 的结果或 A 不可查询的明确错误 |
| 空数据与错误 | 无匹配数据返回成功和空行集；无部署、非法维度、服务不可达分别返回可识别的状态或错误 |
| 构建与部署 | 同一请求使用同一幂等键重复提交，服务只受理一次。能按 ID 查到最终状态；构建成功但部署失败时，两个状态均可辨认 |
