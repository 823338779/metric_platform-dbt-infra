> 使用 superpowers:executing-plans 在当前工作区执行；用户已明确选择上一轮审查中的三个删除项。

**目标：** 删除 native-details、独立部署提交和主动构建取消的接口及专属设计。

**依据：** 本轮用户明确删除三个接口的指令及上一轮业务调用审查。

**实现边界：** 使用现有 FastAPI、Pydantic、SQLAlchemy 和 pytest；只修改 dbt-service。普通资源详情与源码读取、ON_SUCCESS 自动部署、部署历史与当前指针保持不变。停机和失租时的线程等待、未知执行结果与物理目标保护继续保留。

## 决策

- 将资源视图通配路由收窄为明确的 source 路由，native-details 返回 404。
- 删除 DeploymentRequest、独立部署受理及其幂等/CAS 专属分支。自动部署统一从构建受理创建，保留历史 operation 字段作为审计与初始部署识别依据。
- 删除主动取消接口、应用/存储方法、取消标志和 worker 轮询/完成时的取消分支。新库不创建取消标志列；旧库可保留该列作为历史证据，运行代码不再读取。历史 CANCELLED 终态和已受理部署记录仍可读取。
- 不修改调用方产品；native-details 的 Agent 调用迁移属于后续独立任务。
- 更新对应退役行为测试；保留自动部署顺序、失败隔离、历史读取、停机和失租安全断言，不弱化无关测试。
- 不执行真实业务库迁移；验证使用本任务新建的可丢弃数据库，结束后清理。
- 不创建 worktree，不修改已有 vendor/dbt 变更。整份计划完成后创建一个产品仓库提交。
