# 指标维度通路与最少必要切分

用户已确认：每个指标可以为公共输出维度指定独立路径；可以共同查询的指标应尽量保留在同一个 MetricFlow 查询中。

## 契约

QUERY/EXPLAIN 的 groupBy 支持现有 `{optionId, grain}` 和新增 `{name, bindings: {metric: {optionId, grain}}}`。绑定必须恰好覆盖请求中的指标。绑定选项来自同一 build 的单指标 available-dimensions；共享选项和 filters 仍来自整个指标集合。name 为小写 SQL 标识符，不得与指标或其他分组输出重名。时间绑定必须显式指定相同粒度，不能将时间与分类维度对齐。

输出名称声明业务上的键等价；服务不根据标签猜测等价，也不做字符串转换或值映射。调用方须保证各路径键具有相同业务含义及兼容物理类型。绑定模式中的排序使用公共 name，混合共享项仍使用 optionId，指标使用指标名。

绑定模式返回原始维度键。若原生 explain 产生 value_mapping 展示包装，使用其结构化 SQL 计划中的原始 SELECT 重新渲染，避免显示标签覆盖关联键；不解析 SQL 文本、不修改 vendor，也不影响普通查询的映射输出。重复显示标签的真实集成测试必须保持键独立。

## 规划与执行

解析每个指标的完整有序分组路径，按路径、类型和粒度签名归组。共享筛选与时间范围应用于每组。先尝试编译整个候选组；若原生查询校验拒绝组合，按稳定指标顺序尝试放入现有可编译组，否则创建新组。单指标仍不合法则报错。仅捕获原生非法查询异常，不把内部错误或连接故障当作切分信号。该策略优先整体编译，失败时做确定性贪心，不承诺任意兼容关系下的数学全局最优。

每组通过原生结构化参数统一维度别名，MetricFlow 负责计算，服务不重写指标公式。子查询不带 limit/order；最终 SQL 使用各组分组键的 UNION 去重集合，再以空值安全 LEFT JOIN 合并，等价于按键全外连接。单组直接投影，不引入多余关联。最终只输出公共维度及指标，保留缺失值 NULL。最终排序并读取 limit+1 行，沿用 resultTruncated。EXPLAIN 返回与执行完全相同的 SQL。

复用一个 Manifest、引擎和 SQL client，不改变 vendor，不增加依赖。现有无 bindings 请求保持原行为。
所有组仅 explain 编译，最终只调用一次 SQL client.query 取数；不得多次取数后在内存拼接。

## 验收

契约测试覆盖缺失/多余绑定、名称冲突和非法选项；规划测试覆盖四指标归为两组、多维签名、粒度及共享筛选；真实 DuckDB + dbt + MetricFlow 测试验证原生编译和数据库结果，覆盖单组、两组及三组、空键、单侧键、复合键、最终排序/截断、过滤与 EXPLAIN。完整现有测试与 Ruff 检查回归。PostgreSQL/StarRocks 未连接的实库验收需明确说明。
